# Auditoría final, iteración visual y puntos de aprobación

## Auditoría final

Después de implementar, comprueba:

- **Funcionalidad:** ¿se conservaron las funciones existentes?
- **UX:** ¿los flujos son comprensibles?
- **UI:** ¿existe coherencia visual?
- **Design system:** ¿los componentes respetan los tokens?
- **Responsive:** ¿funciona correctamente en distintos tamaños?
- **Accesibilidad:** ¿hay problemas evidentes?
- **Consistencia:** ¿hay estilos o componentes contradictorios?
- **Código:** ¿se introdujo duplicación innecesaria?
- **Referencias:** ¿el resultado está inspirado en las referencias sin convertirse en una copia?

## Iteración visual

Cuando tengas herramientas para ejecutar o visualizar la aplicación (servidor de desarrollo, navegador): implementa, ejecuta, inspecciona visualmente el resultado renderizado, identifica problemas, corrige, vuelve a inspeccionar. Que el proyecto compile no significa que esté bien diseñado — son criterios distintos y ambos importan.

No afirmes haber inspeccionado Refero, una página, un archivo o un repositorio si no tuviste acceso real a ellos.

## Puntos de aprobación

Distingue entre dos tipos de acción:

- **Solo lectura:** analizar, investigar, comparar, inspeccionar, detectar problemas, proponer. Procede sin pedir permiso.
- **Modificación:** editar archivos, reemplazar componentes, modificar el sistema visual, cambiar arquitectura frontend, eliminar componentes, refactors importantes. Para cambios destructivos, irreversibles o de gran alcance sobre un proyecto existente, confirma con el usuario antes de proceder — esto complementa (no sustituye) las reglas de confirmación propias del entorno en el que operes.

## Criterios de calidad

Una buena ejecución logra simultáneamente: funcionalidad, coherencia, claridad, modernidad, originalidad, accesibilidad, responsive, mantenibilidad, consistencia, buena jerarquía y una experiencia de usuario sólida. Nunca sacrifiques usabilidad solo por conseguir una apariencia más llamativa.
