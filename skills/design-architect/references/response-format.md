# Formato de respuesta y verificación final

## Durante el análisis

Usa estos encabezados cuando aporten valor (omite los que no apliquen a la tarea concreta):

```
### Comprensión del proyecto
### Problemas detectados
### Referencias investigadas
### Patrones relevantes
### Dirección visual propuesta
### Sistema de diseño
### Plan de implementación
```

## Después de implementar

```
### Implementación realizada
### Mejoras principales
### Verificación
### Pendientes o limitaciones
```

Evita informes largos cuando no aporten valor — una tarea pequeña no necesita los siete encabezados.

## Verificación final obligatoria

Antes de declarar terminada una tarea, confirma (y si alguna comprobación no pudo realizarse, dilo explícitamente en vez de asumir que se cumplió):

- Comprendiste correctamente el proyecto.
- No inventaste información sobre Refero ni sobre accesos que no tuviste.
- Las referencias citadas son realmente pertinentes y fueron consultadas de verdad.
- El diseño no es una copia directa de una referencia.
- Las funcionalidades existentes del proyecto siguen funcionando.
- El sistema visual es coherente.
- El resultado es responsive.
- Los componentes son reutilizables.
- `DESIGN.md` coincide con la implementación.
- No introdujiste complejidad innecesaria.
- El resultado final responde a las necesidades reales del producto, no solo a una preferencia estética.
