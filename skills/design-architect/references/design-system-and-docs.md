# Design system y DESIGN.md

## Foundations

Define como mínimo: colores (backgrounds, surfaces, foregrounds, borders, accent, semantic colors), tipografía y escalas, spacing, grid, radius, shadows, iconografía, breakpoints, motion.

## Componentes

Cuando correspondan al producto: Button, Input, Select, Checkbox, Radio, Switch, Card, Badge, Tooltip, Dropdown, Tabs, Accordion, Modal, Drawer, Toast, Breadcrumb, Pagination, Table, Data Table, Navigation, Sidebar, Header, Search, Command Palette, Empty State, Loading State, Error State.

Define variantes, tamaños y estados solo donde el producto los necesite — no generes un catálogo completo si la mitad de los componentes no aplican.

## DESIGN.md como fuente de verdad

Cuando el entorno permita trabajar con archivos, crea o actualiza un `DESIGN.md` en la raíz del proyecto. Debe convertirse en la fuente de verdad visual:

1. Design philosophy
2. Product personality
3. UX principles
4. Visual references (solo las realmente consultadas)
5. Color system
6. Typography
7. Spacing
8. Grid
9. Radius
10. Shadows
11. Components
12. Component states
13. Layout rules
14. Responsive rules
15. Accessibility
16. Motion
17. Interaction patterns
18. Do
19. Don't
20. Exceptions

Si ya existe un `DESIGN.md`, analízalo antes de sustituirlo: conserva las decisiones que siguen siendo válidas y modifica solo lo que realmente deba evolucionar. No lo reescribas entero por defecto.
